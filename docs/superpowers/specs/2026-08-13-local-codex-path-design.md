# Настройка локального пути Codex

## Цель

Локальный запуск должен использовать явно настроенный и действительно работающий бинарник Codex, чтобы ACP не переходил в `MODEL_UNAVAILABLE` из-за сломанного `codex` в `PATH`.

## Решение

- Локальный `.env` задаёт `CODEX_PATH=/Applications/ChatGPT.app/Contents/Resources/codex`.
- `scripts/run-local.sh` загружает переменные из корневого `.env`, если файл существует. Уже заданные переменные окружения имеют приоритет над значениями файла.
- Если `CODEX_PATH` не задан, скрипт сначала рассматривает `codex` из `PATH`, а затем встроенный бинарник ChatGPT на macOS.
- Выбранный бинарник проверяется командой `--version` до запуска backend и frontend. Отсутствующий или сломанный бинарник приводит к немедленной понятной ошибке, а не к позднему `MODEL_UNAVAILABLE`.
- `.env.example` документирует `CODEX_PATH`, но не содержит пользовательский абсолютный путь.

## Границы

Изменение касается только локального запуска через `scripts/run-local.sh`. Docker-конфигурация и серверная логика оценки не меняются. Существующая `.env` остаётся незакоммиченной.

## Проверка

Автоматический shell-тест запускает скрипт в режиме проверки конфигурации с временными исправным и сломанным бинарниками. После реализации локальный сервер перезапускается, а `/api/system/status` должен вернуть `acpAvailable: true` после успешного ACP-вызова.
