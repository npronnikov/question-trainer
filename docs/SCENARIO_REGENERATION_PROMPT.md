# Промпт для перегенерации 56 карточек тренажёра

Ты — ведущий методист тренажёра критического и нестандартного мышления. Создай новый, полностью переработанный набор из **56 учебных карточек** на русском языке для приложения «Вопросы-взломщики».

Я приложу два файла:

1. `theory-expansion.json` — исследовательская база с определениями, механизмами, протоколами, кейсами, упражнениями и источниками.
2. `scenarios.js` — исходные 28 карточек, которые можно использовать только как примеры формата и уровня сложности.

## Цель

Новый набор должен учить распознавать, **какое движение мысли совершает вопрос**, а не угадывать категорию по отдельным словам. Сделай ровно в два раза больше карточек, чем сейчас: **56 карточек, по 8 карточек для каждой из семи категорий**.

## Категории и обязательный порядок

Используй только эти ID и сохрани этот порядок категорий:

1. `INVERSION` — инверсия: цель или желаемый результат заменяется противоположным, после чего выводы обращаются в защитные действия.
2. `HYPERBOLE` — гипербола / 10×: один или несколько параметров задачи доводятся до крайности — масштаб, срок, бюджет, цена, качество или ограничение.
3. `CROSS_DISCIPLINE` — кросс-дисциплина: механизм решения переносится из другой отрасли, науки, профессии, природной или социальной системы.
4. `FUTURISM` — футуризм: задача рассматривается из конкретного будущего состояния; путь, последствия или ранние сигналы восстанавливаются назад.
5. `PROVOCATION` — провокация: отменяется или ставится под сомнение правило, допущение, запрет, ритуал либо «священная корова».
6. `REFRAMING` — рефрейминг: меняется рамка, единица анализа, определение проблемы, заинтересованная сторона или критерий результата.
7. `SIMPLIFICATION` — упрощение: элементы удаляются до минимального ядра ценности; решение пересобирается с нуля или из первых принципов.

## Требования к набору

- Создай ровно 56 объектов: по 8 объектов на каждый `category`.
- ID должны быть уникальными и идти последовательно:
  - `inv-01` … `inv-08`;
  - `hyp-01` … `hyp-08`;
  - `cross-01` … `cross-08`;
  - `future-01` … `future-08`;
  - `prov-01` … `prov-08`;
  - `ref-01` … `ref-08`;
  - `simp-01` … `simp-08`.
- Не копируй текущие карточки дословно. Сохраняй удачные принципы, но придумай новые ситуации, вопросы и объяснения.
- Используй исследование как методическую основу. Исторические кейсы из него можно превращать в современные учебные ситуации, но не выдавай вымышленные детали за факты.
- Распредели контексты разнообразно: продукт, стратегия, команда, операции, продажи, маркетинг, образование, медицина, государственные сервисы, карьера, финансы, разработка, дизайн, логистика, устойчивость и повседневные решения.
- Не делай более двух карточек одной категории из одной предметной области.
- Не используй узнаваемые названия компаний или людей без необходимости: карточка должна проверять технику, а не знание факта.
- Ситуация должна содержать достаточно контекста для классификации, но не называть правильную технику.
- Вопрос должен звучать естественно и быть реально применимым на рабочей сессии.
- Не вставляй название категории и слишком очевидные маркеры вроде «применим инверсию» в `situation` или `question`.
- Избегай пустых лозунгов, однотипных формулировок и вопросов, на которые можно ответить только «да» или «нет».
- Делай соседние категории различимыми по механике:
  - инверсия меняет направление цели, провокация отменяет правило;
  - гипербола меняет величину параметра, упрощение удаляет элементы;
  - рефрейминг меняет определение проблемы, кросс-дисциплина импортирует внешний механизм;
  - футуризм обязательно использует осмысленную временную дистанцию, а не просто прогноз.
- Примерно 40% карточек сделай умеренно сложными: поверхностная лексика может напоминать соседнюю категорию, но механизм должен давать один лучший ответ.
- Не создавай карточек, для которых две категории одинаково правильны.

## Требования к полям

Каждый объект должен содержать только следующие поля:

```json
{
  "id": "inv-01",
  "category": "INVERSION",
  "domain": "КОМАНДА",
  "situation": "Краткое описание реальной ситуации в 1–2 предложениях.",
  "question": "Один вопрос-взломщик в русских кавычках.",
  "explanation": "Объяснение в 2–3 предложениях: какое точное преобразование выполнено, почему это данная категория и чем она отличается от ближайшей похожей категории."
}
```

Ограничения:

- `domain`: 1–3 слова, прописными буквами;
- `situation`: 120–280 символов;
- `question`: 70–220 символов;
- `explanation`: 160–420 символов;
- никаких дополнительных полей;
- никаких Markdown-ссылок, сносок или ссылок на источники внутри карточек.

## Внутренняя проверка перед ответом

Перед выдачей результата молча проверь:

1. Объектов ровно 56.
2. Каждая категория встречается ровно 8 раз.
3. Все ID уникальны и соответствуют указанным диапазонам.
4. Использованы только семь разрешённых ID категорий.
5. Все шесть полей заполнены, дополнительных полей нет.
6. Нет дословных повторов из `scenarios.js` и дублей внутри нового набора.
7. У каждой карточки существует один лучший ответ.
8. `explanation` явно объясняет механизм и границу с ближайшей категорией.
9. JSON синтаксически валиден: без комментариев, trailing comma и JavaScript-конструкций.

Если обнаружена ошибка, исправь её до ответа. Не сообщай промежуточные рассуждения и результаты внутренней проверки.

## Формат ответа

Верни **только один валидный JSON-массив из 56 объектов** в кодовом блоке `json`. Не добавляй вступление, заключение, статистику или пояснения вне JSON.
